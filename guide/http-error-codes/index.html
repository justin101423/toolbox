404, 500, 403… 에러 코드의 의미 — 방문자와 운영자가 할 일

도구상자 지기가이드약 4분2026.06.11

"404 Not Found", "500 Internal Server Error" — 인터넷을 쓰다 보면 누구나 만나는 화면입니다. 숫자가 뜻하는 바를 알면 "내 잘못인지, 사이트 잘못인지, 기다리면 되는지"를 바로 판단할 수 있습니다. 자주 만나는 에러 코드의 의미와 대처를 정리합니다.

이 글의 순서
  1. 첫 자리 숫자가 책임 소재를 말해 준다
  2. 자주 만나는 에러 6가지
  3. 방문자가 해 볼 수 있는 것
  4. 운영자라면 — 점검 포인트

첫 자리 숫자가 책임 소재를 말해 준다

HTTP 상태 코드는 세 자리 숫자이고, 첫 자리가 큰 분류입니다.

  • 2xx (성공) — 정상 처리. 에러 화면에선 볼 일이 없습니다.
  • 3xx (리다이렉트) — 페이지가 다른 주소로 이동했다는 안내. 브라우저가 알아서 따라갑니다.
  • 4xx (요청 쪽 문제) — 주소가 틀렸거나, 권한이 없거나, 요청 자체가 잘못된 경우.
  • 5xx (서버 쪽 문제) — 요청은 맞는데 서버가 처리하지 못한 경우. 방문자 잘못이 아닙니다.
한 줄 요약: 4로 시작하면 "주소·권한을 확인", 5로 시작하면 "사이트 문제 — 잠시 후 다시".

자주 만나는 에러 6가지

  • 400 Bad Request — 요청 형식이 잘못됨. 주소에 이상한 문자가 끼었거나 쿠키가 손상된 경우가 많습니다.
  • 401 Unauthorized — 로그인이 필요합니다. "누구인지 모르겠다"는 뜻입니다.
  • 403 Forbidden — 로그인했더라도 볼 권한이 없습니다. "누구인지 알지만 허용 안 됨"입니다.
  • 404 Not Found — 그 주소에 페이지가 없습니다. 오타, 삭제·이동된 페이지가 원인입니다.
  • 500 Internal Server Error — 서버 내부 오류. 사이트 코드의 버그인 경우가 대부분입니다.
  • 502/503 — 중간 서버가 응답을 못 받았거나(502), 서버가 과부하·점검 중(503). 보통 일시적입니다.

방문자가 해 볼 수 있는 것

  1. 새로고침 — 일시적 오류(특히 5xx)는 이걸로 끝나는 경우가 많습니다.
  2. 주소 확인 — 404라면 주소 오타부터. 검색으로 페이지를 다시 찾는 것도 방법입니다.
  3. 로그인·캐시 — 401·403은 다시 로그인, 400은 쿠키·캐시 삭제가 통하는 경우가 있습니다.
  4. 기다리기 — 502·503은 사이트가 복구 중이라는 신호입니다. 몇 분 뒤 다시 시도하세요.

운영자라면 — 점검 포인트

  • 404 관리: 페이지 주소를 바꾸면 301 리다이렉트를 걸고, 서치 콘솔에서 404 나는 URL을 주기적으로 확인하세요. 깨진 내부 링크는 방문자와 검색엔진 모두에게 막다른 길입니다.
  • 500 추적: 서버 에러 로그에 원인이 남습니다. 재현 조건(특정 페이지·특정 입력)을 찾는 것이 첫걸음입니다.
  • 503 활용: 점검 시간에는 의도적으로 503과 Retry-After 헤더를 내보내는 것이 검색엔진에 "곧 돌아온다"는 올바른 신호가 됩니다.
자주 묻는 질문
Q. 404와 500의 차이는 뭔가요?

책임 소재가 다릅니다. 404(Not Found)는 요청한 주소에 페이지가 없다는 뜻으로, 주소 오타나 삭제·이동된 페이지가 원인입니다. 500(Internal Server Error)은 주소는 맞지만 서버 내부에서 오류가 났다는 뜻입니다. 첫 자리가 4면 요청 쪽 문제, 5면 서버 쪽 문제라고 기억하면 대부분의 에러를 읽을 수 있습니다.

Q. 502, 503 에러는 기다리면 해결되나요?

대부분 그렇습니다. 502(Bad Gateway)는 중간 서버가 뒤쪽 서버로부터 정상 응답을 받지 못한 상태, 503(Service Unavailable)은 서버가 과부하나 점검으로 일시적으로 요청을 받을 수 없는 상태입니다. 둘 다 서버 쪽의 일시적 문제인 경우가 많아 몇 분 뒤 새로고침하면 해결되는 일이 흔합니다. 계속되면 서비스 공지나 상태 페이지를 확인하세요.

Q. 내 블로그·사이트에서 404가 자주 나면 SEO에 나쁜가요?

404 자체는 자연스러운 현상이고 페널티 대상이 아닙니다. 문제는 사이트 안의 링크나 외부에서 들어오는 링크가 404로 이어질 때입니다. 방문자와 검색엔진 모두 막다른 길을 만나게 되죠. 페이지 주소를 바꾸거나 삭제했다면 새 주소로 301 리다이렉트를 걸고, 서치 콘솔의 색인 보고서에서 404가 나는 URL을 주기적으로 점검하는 것이 좋습니다.
